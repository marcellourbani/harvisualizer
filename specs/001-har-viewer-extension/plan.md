## Summary

This feature introduces a VSCode extension for viewing and analyzing HAR (HTTP Archive) files. It will provide a custom editor that displays a filterable list of HTTP calls from a HAR file. For large HAR files, a conditional lazy-loading strategy will be employed to efficiently parse entries without consuming excessive memory. The core parsing logic and UI components will be built as separate, reusable packages. The viewer's theme will synchronize with the active VSCode theme (light/dark) for a seamless user experience. Communication between the UI component and the extension host will be handled through a dependency injection pattern, ensuring the UI package remains fully decoupled from the VSCode environment.

## Architecture

The `har-parser` will implement a conditional parsing strategy. For HAR files larger than a configurable threshold (defaulting to 50MB), it will use `stream-json` to lazily load `log.entries` one by one, allowing for efficient processing of very large files without loading the entire content into memory. Smaller files will be parsed in their entirety for simplicity and faster access.

The `har-viewer` component will be fully decoupled from the VSCode environment through dependency injection.
1.  **Interface Definition**: The `har-viewer` package will define a generic communication interface (e.g., `CommunicationProvider`) with methods for sending and receiving data.
2.  **Component Implementation**: The React components within `har-viewer` will use this interface to communicate.
3.  **VSCode-specific Implementation**: The `vscode-extension` package will create a concrete class that implements the `CommunicationProvider` interface using VSCode's `postMessage` API for webviews. It will also be responsible for detecting the current VSCode theme (`window.activeColorTheme`) and listening for theme changes (`window.onDidChangeActiveColorTheme`).
4.  **Injection and Communication**: The `vscode-extension` will inject its `CommunicationProvider` into the `har-viewer` component. It will send an initial `themeChanged` message upon load and subsequent messages whenever the VSCode theme changes. The `har-viewer` will listen for these messages and apply the corresponding CSS classes (`light` or `dark`) to its root element.

This pattern ensures that the `har-viewer` package can be used in other environments (e.g., a standalone web app) by simply providing a different communication provider.

## Technical Context

**Language/Version**: TypeScript (latest), Node.js (LTS)
**Primary Dependencies**: React (latest), VSCode API, `stream-json`
**Storage**: N/A
**Build Tools**: Vite (for har-viewer), esbuild (for vscode-extension)
**Testing**: Jest, React Testing Library, Vitest (for har-viewer), `@vscode/test-electron`
**Target Platform**: VSCode (Desktop) with Webview
**Project Type**: Monorepo (npm workspaces)
**Performance Goals**:
  - Initial list load < 2s for 1000 entries
  - UI filtering < 500ms
**Constraints**:
  - `har-parser` and `har-viewer` packages must not have any VSCode dependencies.
  - Configurable file size threshold for lazy loading (default 50MB).
**Scale/Scope**:
  - The extension will support HAR files generated by modern browsers (Chrome, Firefox, Edge).
  - The initial version will focus on viewing and filtering. Editing/modifying HAR files is out of scope.

## Testing Notes

Example HAR files are available in the `examples/` directory in the repository root. These files are provided for development and testing purposes. They will not be part of the final repository due to their size and potential privacy concerns. When setting up automated tests, these files should be accessed from their location or copied to a temporary testing environment.
